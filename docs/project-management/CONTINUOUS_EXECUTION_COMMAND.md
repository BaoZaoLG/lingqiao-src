# 灵桥项目持续执行总指令

## 使用方法

将下方“可直接粘贴的总命令”完整发送给 Codex。它不是操作系统层面无法终止的进程；它的含义是：在没有真正硬阻塞的情况下，不因批次完成、测试失败、上下文切换或普通不确定性而停下来询问，始终依靠进度文件继续推进。

## 十个大任务

1. **全局总控、架构与仓库治理**：执行 `SESSION_01_TASK_QUEUE.md` 的 1200 项任务，覆盖根目录边界、架构、配置、文档、跨模块关系、技术债、运行产物与 Java 迁移总方案。
2. **API、协议与兼容性**：执行 `SESSION_02_TASK_QUEUE.md` 的 1330 项任务，覆盖全部 Go 路由、Handler、DTO、状态码、错误码、鉴权入口、OpenAPI、Web API 客户端与 C++ API 客户端。
3. **业务逻辑与状态机**：执行 `SESSION_03_TASK_QUEUE.md` 的 1250 项任务，覆盖 Service、UseCase、领域规则、状态流转、事务边界、幂等、并发、调度器和跨模块业务语义。
4. **数据库、迁移与数据一致性**：执行 `SESSION_04_TASK_QUEUE.md` 的 1896 项任务，覆盖 SQLite schema、旧数据迁移、Repository、查询、索引、事务、分页、唯一性、备份恢复和数据兼容。
5. **安全、认证与供应链防护**：执行 `SESSION_05_TASK_QUEUE.md` 的 1100 项任务，覆盖 HMAC、令牌、密码、权限、密钥、证书、CORS、CSRF、XSS、SQL 注入、路径穿越、上传下载、日志脱敏和发布签名。
6. **Web 前端与用户体验**：执行 `SESSION_06_TASK_QUEUE.md` 的 2320 项任务，覆盖管理端与代理端 18 个页面、路由、DOM、表单、权限 UI、状态管理、API 调用、加载/空/错状态、可访问性、响应式样式和 TypeScript 构建。
7. **构建、配置、依赖、CI/CD 与交付**：执行 `SESSION_07_TASK_QUEUE.md` 的 1293 项任务，覆盖 CMake、Go、npm、Maven、PowerShell、WiX、GitHub Actions、环境变量、版本、制品、部署与回滚。
8. **测试体系与质量门禁**：执行 `SESSION_08_TASK_QUEUE.md` 的 1250 项任务，覆盖 Go/C++/TypeScript/PowerShell/Java/E2E 测试、边界与异常分支、回归测试、稳定性、覆盖率和统一质量门禁。
9. **死代码、重复代码与可维护性**：执行 `SESSION_09_TASK_QUEUE.md` 的 1050 项任务，覆盖未引用文件/导出、重复函数/常量/类型、无意义包装、旧注释、误导命名和生成产物；删除前必须证明不可达且未被构建或运行时加载。
10. **Java 后端渐进迁移**：执行 `SESSION_10_TASK_QUEUE.md` 的 1050 项任务，覆盖 Spring Boot 侧车、Go 兼容契约、DTO/错误/鉴权/Repository/Flyway、影子读、灰度切换、监控与逐模块回滚；默认不得替换 Go 生产入口。

合计：**13,739 个已落到具体文件、接口、模块或验证动作的子任务**。

## 可直接粘贴的总命令

```text
请为当前工作区创建并持续执行一个持久目标：彻底完成“灵桥项目全仓库治理与交付稳定化”，覆盖项目的每个源码目录、配置、接口、数据表、构建入口、测试入口、安装发布链路、文档与运行边界。

工作区根目录：C:\Users\Li\Downloads\Lingqiao_src

这是持续执行任务。除非遇到真正无法在本地解决的硬阻塞，否则不要停下来征求确认，不要只给计划，不要只做审计，不要在完成一个批次后结束。持续读取任务队列、修改、验证、记录进度并进入下一批；如果任务因上下文切换、工具超时、测试失败或会话续接而中断，必须从进度文件中的第一个未完成任务自动恢复，而不是重新开始或等待我提醒。

一、唯一任务源
严格按以下顺序完成现有任务队列，禁止重新生成重复的大清单来代替执行：
1. SESSION_01_TASK_QUEUE.md：全局总控、架构、仓库边界、文档与跨模块治理，共 1200 项。
2. SESSION_02_TASK_QUEUE.md：API、Handler、DTO、错误码、OpenAPI 与客户端契约，共 1330 项。
3. SESSION_03_TASK_QUEUE.md：Service、领域规则、状态机、幂等、并发与事务边界，共 1250 项。
4. SESSION_04_TASK_QUEUE.md：SQLite、迁移、Repository、查询、索引、事务与数据一致性，共 1896 项。
5. SESSION_05_TASK_QUEUE.md：认证、授权、密码、令牌、密钥、证书、Web/文件/供应链安全，共 1100 项。
6. SESSION_06_TASK_QUEUE.md：管理端、代理端、页面、交互、状态、样式、可访问性与类型检查，共 2320 项。
7. SESSION_07_TASK_QUEUE.md：构建、依赖、配置、脚本、CI/CD、安装、发布与回滚，共 1293 项。
8. SESSION_08_TASK_QUEUE.md：单元、集成、E2E、回归、异常分支、稳定性与质量门禁，共 1250 项。
9. SESSION_09_TASK_QUEUE.md：死代码、重复代码、无效抽象、误导命名与生成物治理，共 1050 项。
10. SESSION_10_TASK_QUEUE.md：Java Spring Boot 侧车与渐进兼容迁移，共 1050 项。

二、开始前必须执行
1. 读取适用范围内的所有 AGENTS.md、README、架构文档、进度文件、BUSINESS_QUESTIONS.md 和 CROSS_MODULE_REPORT.md。
2. 检查 git status，建立“用户已有改动保护清单”。当前工作区存在大量已修改和未跟踪文件，必须视为用户资产；禁止 reset、checkout 覆盖、clean、批量删除或回滚不是你本批创建的内容。
3. 读取 SESSION_*_PROGRESS.md 和每个队列中的完成标记，定位每个会话第一个未完成 ID。
4. 若某会话缺少进度文件，创建 SESSION_XX_PROGRESS.md；只记录事实、改动、验证结果、失败原因和下一任务 ID。
5. 建立或维护 MASTER_EXECUTION_PROGRESS.md，记录十个大任务的总数、已完成数、当前 ID、阻塞项、最后验证命令与时间。

三、持续执行规则
1. 一次处理 10 至 50 个彼此相关的小任务；优先处理同一调用链或同一文件集，避免无意义地逐条打开和关闭文件。
2. 每个小任务必须经历：读取上下文 → 查引用/调用链 → 判断根因 → 最小修改 → 添加或更新测试 → 运行针对性验证 → 更新完成标记与进度。
3. 任务只是审计项但发现明确缺陷时，应直接修复；涉及无法确定的产品语义时，记录到 BUSINESS_QUESTIONS.md，选择最保守、向后兼容、可回滚的实现继续推进，不要因为普通歧义停止。
4. 跨模块问题写入 CROSS_MODULE_REPORT.md，并在对应两个或多个队列中互相引用；不得在一个模块里偷偷改变另一个模块的公开契约。
5. 修复根因，不做掩盖错误的表面补丁；保持改动最小，不顺手重写无关模块。
6. 不得伪造完成状态。只有代码/文档动作完成且所需验证通过，才能把任务标记为完成。
7. 不得通过删除测试、放宽断言、跳过安全检查、吞掉错误或硬编码测试值来获得通过。
8. 删除文件、导出、接口或兼容路径前，必须同时检查源码引用、构建配置、测试、动态加载、脚本、文档与发布制品；证据不足则保留并记录。
9. 涉及数据库结构、认证协议、更新协议、密钥格式、安装升级或 Java 切流时，必须先有兼容测试与回滚路径。
10. 不主动提交、不创建分支、不推送远端，除非我另行明确要求。

四、验证门禁
按改动范围先运行最小验证，再运行模块验证；每完成一个大任务运行一次全量门禁。

最低验证集合：
- Web：在 server/web 运行 npm run typecheck 和 npm run build。
- Go：在 server 运行相关包测试，批次稳定后运行 go test ./...。
- E2E：在 e2e_test 运行 go test ./...；涉及启动、迁移、认证、证书或端口时必须执行。
- C++：运行对应 CMake configure/build 和现有客户端回归脚本；涉及 Hook、CEF/V8、注入、线程或内存生命周期时必须运行相应测试目标。
- AutoExam：运行 packages/autoexam/build.ps1 与 scripts/autoexam_multimodal_provider_regression_test.ps1。
- Java：在 server-java 运行 Maven 测试；保持 sidecar 默认关闭，不占用 Go 生产端口，不默认写现有数据库。
- 发布：涉及版本、安装或制品时，验证 scripts/release.ps1、installer 脚本、WiX 输入、哈希、签名、升级和回滚路径。
- 总门禁：运行 scripts/check.ps1；若失败，区分“本批回归”和“预先存在问题”，本批回归必须修复，预先存在问题必须记录并继续处理可执行任务。

五、失败与恢复策略
1. 命令失败时先保存输出摘要到当前 SESSION_XX_PROGRESS.md，然后定位根因并最多进行三轮有依据的修复与复验；不要原样重复失败命令。
2. 遇到环境缺失时，优先使用项目已有依赖和脚本；可以安全安装的开发依赖则安装并记录，不能安装则继续完成不依赖它的任务。
3. 遇到端口占用、临时文件、构建缓存或测试残留时，只清理本批确认创建且路径经过验证的对象，禁止递归清理不确定目录。
4. 遇到与用户现有改动冲突时，保留用户改动并调整方案；不得覆盖或回滚。
5. 只有以下情况可认定为硬阻塞：缺少必须由我提供的秘密/凭据；必须访问而当前无法访问的外部系统；不可替代的工具链完全缺失且无法安装；产品语义存在两种会造成不可逆数据或安全后果的选择。硬阻塞时记录精确任务 ID、证据、已尝试动作和最小问题，然后继续所有不受影响的任务。
6. 若会话被系统暂停或上下文结束，下次恢复时先读 MASTER_EXECUTION_PROGRESS.md 与对应 SESSION_XX_PROGRESS.md，直接从记录的 next_task_id 继续。

六、优先级
P0：数据损坏、认证绕过、密钥泄露、任意文件读写、远程代码执行、更新链路劫持、安装升级破坏。
P1：公开接口错误、状态机错误、事务不一致、并发竞态、客户端崩溃、发布失败、无法回滚。
P2：缺失测试、错误处理、性能、可访问性、兼容性漂移、维护成本。
P3：命名、文档、格式、低风险重复与非关键清理。
在队列顺序内优先处理更高优先级，但必须保留任务 ID 可追踪性。

七、完成标准
只有同时满足以下条件，目标才算完成：
1. SESSION_01 至 SESSION_10 共 13,739 个任务全部有真实完成记录，或有经证据证明“不适用/重复/被其他任务覆盖”的关闭说明。
2. 十个进度文件和 MASTER_EXECUTION_PROGRESS.md 全部更新到最终状态。
3. BUSINESS_QUESTIONS.md 与 CROSS_MODULE_REPORT.md 中可由代码事实解决的项目已关闭；剩余项目明确说明为何必须由产品负责人决定。
4. Web、Go、E2E、C++、AutoExam、Java 和发布链路的适用验证均已执行并记录。
5. scripts/check.ps1 通过；若存在无法由仓库修复的环境限制，必须提供可复现证据和替代验证结果。
6. README、架构、API、配置、安全、备份恢复、发布与回滚文档和最终实现一致。
7. 输出最终报告：完成数量、修改文件、关键修复、测试结果、遗留风险、业务待决项、回滚方法和建议发布步骤。

现在立即开始：先创建持久目标和 MASTER_EXECUTION_PROGRESS.md，保护现有工作区改动，定位十个队列的首个未完成任务，然后连续执行。不要只回复计划。
```

## 现实边界

- 任何命令都无法抵抗断电、进程被杀、系统重启、权限撤销或工具服务中断。
- 这份指令通过进度文件、任务 ID、批次验证和恢复规则实现“可恢复的持续执行”，比要求单个进程永不退出更安全。
- 当前仓库存在大量未提交改动和运行/构建产物，持续执行时必须优先保护这些内容，不能用清理工作区的方式追求所谓干净基线。
